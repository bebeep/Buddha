## 二、为什么要做"同音字替换"

中文 TTS 读汉字时，多音字只能靠训练语料里的常见读法猜。佛经里偏偏全是专读：

- 「南无」要读 **ná mó**，TTS 会念成 *nán wú*
- 「给孤独园」的「给」要读 **jǐ**，TTS 会念成 *gěi*
- 「兜率天」的「率」要读 **shuài**，TTS 会念成 *lǜ*
- 「维摩诘」的「诘」要读 **jié**，TTS 会念成 *jí*

做法是：把字换成**同音但只有一种读音**的常用字，再把替换后的文本交给 TTS。

```
舍利  shè lì   ->  社利      舍(she4) -> 社
南无  ná mó    ->  拿魔      南(na2)->拿, 无(mo2)->魔
兜率天 dōu shuài -> 兜帅天    率(shuai4) -> 帅
给孤独园 jǐ ...  -> 己孤独园   给(ji3) -> 己
```

选字有两条硬约束，否则会引入新的错误：

1. **只用 GB2312 一级常用字**（3755 个），保证 TTS 一定认识；
2. **候选字的主读音必须是目标读音**。比如「剥」主读音是 bāo、bō 在第二，就不能用；
   而「惹」主读音就是 rě，可以用。

223 条里 59 条做了替换，其余 164 条本身读音就与常见读法一致，保留原字。

## 四、已知局限

1. **「伽」(qié) 和「佛」(fó) 没有可用的同音常用字**，13 条里这两个字保留原字。
   但这俩字所在的词（瑜伽、僧伽、佛…）都是超高频词，TTS 读音稳定，实测无问题。
2. **不是诵经调**。生成的是字正腔圆的播报音，没有木鱼节奏和梵呗唱诵的韵味。
   要诵经腔只能真人录。
3. **单字词条听起来可能突兀**（比如只念一个「佛」），但只有 2 条是单字。
4. 机器合成，**建议抽听 P1 的 66 条**再上线。

## 五、技术参数

| 项 | 值 |
| --- | --- |
| 音色 | `zh-CN-YunyangNeural`（男，新闻播报） |
| 语速 | -10%（默认偏快，放慢一点更稳） |
| 采样率 | 22050 Hz 单声道 |
| 码率 | 48 kbps MP3 |
| 静音处理 | 自动裁掉首尾静音（原始合成每条固定 1.87 秒，裁后 0.38-1.75 秒） |
| 响度 | 峰值归一化到 -1 dB，全部一致，不会有的响有的轻 |
| 命名 | `序号_拼音.mp3`，如 `001_bo_re.mp3`、`042_dou_shuai_tian.mp3` |

`_音频_逐字/_音频清单.csv` 是索引，字段：

```
id, priority, term, reading, spokenText, changes, unfixable, kind, file, durationMs, bytes
```

`spokenText` 是实际送进 TTS 的文本（即同音字版），App 里不显示，只用于排查。

## 六、App 接入（已完成）

音频全部塞进 APK 的 assets，不联网、不走 OSS，点开立刻响。

```
baseLib/src/main/assets/reading/audio/001_bo_re.mp3 ...   共 220 个文件，936 KB
```

落地的几个点：

| 项 | 做法 |
| --- | --- |
| 文件命名 | 原样沿用 `序号_拼音.mp3`，同读音的重复条目只留一份（220 个） |
| 字典 | `reading_dict.tsv` 加第 5 列 `audio`，存文件名，空表示没录音 |
| 绑定方式 | **按读音绑，不按词绑**：`bō rě bō luó mì` 这一串音对「般若波罗蜜」和「般若波羅蜜」都成立，繁体条目共用简体那条音频，不用另外录 |
| 覆盖率 | 6218 行里 365 行绑上音频；**会加下划线提示的 108 个标记词条 100% 有音频** |
| 播放 | `ReadingPlayer` 单例 MediaPlayer，优先按 fd 零拷贝读，读不到再整条进内存兜底 |
| 入口 | 点字弹窗里多一个「听读音」按钮，没录音的词不显示；弹窗关掉就停 |

顺带把读音库的错读音也同步了：`迦叶`（含大迦叶／十力迦叶／迦叶波）、`无著`、`释迦牟尼`、`拘那含牟尼`，
简繁 13 行一起改，和音频一致。

要扩到全部词条，只需往 `_录音清单.tsv` 加词、重跑 `gen_audio_strict.py` 和 `_tmp/bind_audio.py`。
